In this work, I compared Binary Search Tree and Hash Table. For the test, I used the elements specified in the task and tested insert, search and delete. 
At first, I didn't use resizing in my Hash Table. Because of this, the Hash Table was slow for 10000 elements.
Before resizing
10000,HashTable,insert,16694300
10000,HashTable,search,15118660
10000,HashTable,delete,14405840
Then I added resizing and rehashing. After this, the Hash Table worked much faster.
After
10000,HashTable,insert,4072340
10000,HashTable,search,553180
10000,HashTable,delete,680680
Binary search tree usually has O(log n) time for insert, search and delete, but in the worst case it can be O(n). Hash Table usually has O(1) time, but in the worst case it can be O(n). Hash Table was faster for search and delete. Binary search tree was faster for insert with 1000 and 10000 elements. Hash Table can be slower during insert because it sometimes needs resizing. Binary search tree can be slower if the tree is not balanced. Hash Table can be slower if many values go to the same place. For fast search, I think Hash Table is better. Binary search tree is useful when we need data in order.
So, in my test, Hash Table was better for search and delete, but Binary search tree was better for insert with bigger input sizes. Binary search tree is also useful when we need data in order.
